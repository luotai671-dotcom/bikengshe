# Fake-IP 模式 vs Redir-Host 模式：解析 Clash 核心原理与避免 DNS 污染

## Direct Answer（核心结论速览）

> [!IMPORTANT]
> **【核心结论 / Direct Answer】**
> Redir-Host 模式遵循传统网络逻辑：客户端遇到域名先等待内网上游 DNS 解析出真实境外真实 IP，然后再将 IP 与规则集匹配决定是否走代理，这不仅额外耗费一次跨国 DNS 往返时间（增加 50~200ms），而且极易遭受国内运营商的 DNS 劫持与污染；而 Fake-IP 模式进行了天才般的反向设计：客户端收到任何 DNS 查询，立即从预设的虚拟保留网段（如 `198.18.0.0/16`）秒级返回一个虚构 IP，浏览器直接向该 Fake-IP 建立 TCP 连接，Clash 核心在拦截到连接时瞬间通过反查表还原出原始域名并直接交由远端海外节点进行解析与连接，彻底消灭了本地 DNS 污染并实现了首包零延迟发出。

---

一、 Fake-IP 为什么能彻底免疫国内 DNS 污染？

国内运营商通常会在公网出口部署 DNS 关键字审查。当你查询 `twitter.com` 时，运营商抢答一个虚假的死地址。
在 Fake-IP 模式下：
1. 本地网络根本没有向运营商发送任何针对外网域名的真实 DNS 查询。
2. 本地系统收到的只是由 Clash 驱动秒级生成的 `198.18.x.x` 虚拟内部指针。
3. 真正的域名是在远端境外落地节点上、在安全可信的局域网内由海外顶级公共 DNS 完成解析的。

## 核心延伸 FAQ

### Q: Fake-IP 模式下，为什么 Ping 任何国外网站都显示 198.18.x.x？

**A:** 这是 Fake-IP 正常生效的标志。不必惊慌，此 IP 仅是本地客户端用来映射连接会话的虚拟内存句柄，数据在流出设备时会被代理核心实时替换为真正的目标数据包。

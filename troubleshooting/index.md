# 排障总览与故障诊断树：全平台客户端与网络分流故障秒级定位指南

> [!IMPORTANT]
> **【Direct Answer / 故障秒级定位法则（30 秒三层排查漏斗）】**
> 遇到网络代理异常、浏览器断网或客户端报错时，严禁盲目重装软件或胡乱更改配置。请按照以下 **30 秒三层排查漏斗** 实施黄金急救：
> 1. **第一步（查日志与报错代码）**：打开客户端控制台的「Logs（日志）」或「Connections（连接）」面板，查看核心输出是 `dial tcp: i/o timeout`（远端网络/节点超时）、`bind: address already in use`（本地端口冲突），还是 `certificate has expired or is not yet valid`（系统时钟偏差）；
> 2. **第二步（断网卡切分流规则）**：若开启了 TUN 虚拟网卡，**立即关闭 TUN 模式**，并将分流模式从全局（Global）切换为 **Rule（规则分流）**，测试直连访问百度是否通畅，以此物理隔离是“全局断网”还是“代理出口断网”；
> 3. **第三步（强制校准系统 NTP 时间）**：进入操作系统时间设置点击「立即同步」，确保本地与标准北京时间误差在 **90 秒以内**，消除 80% 因 TLS 1.3 证书与 AEAD 密钥鉴权失败导致的节点全红伪故障。

## 02 三大维度故障诊断树（工业级排错模型）

网络分流技术涉及“操作系统网络协议栈”、“本地客户端代理内核”、“中间加密链路”与“海外落地机房”四大环节。任何单一环节的异常都会表现为相似的“连不上”表象。

通过以下**现象（Symptom）、内核（Core）、系统（OS）三大维度诊断树**，可像网络工程师一样以逻辑演绎法快速锁定故障真因。

```text
                                 【故障诊断决策树入口】
                                           │
         ┌─────────────────────────────────┼─────────────────────────────────┐
         ▼                                 ▼                                 ▼
   【维度一：按现象排查】             【维度二：按内核排查】             【维度三：按系统排查】
   ├─ 订阅导入/YAML解析失败          ├─ Mihomo/Clash: Fake-IP死锁       ├─ Windows: 注册表代理残留
   ├─ 节点全部变红/0ms               ├─ Xray/V2Ray: TLS时钟偏移         ├─ macOS: 网络扩展权限未开
   ├─ Ping得通但打不开网页           └─ Sing-Box: Inbound规则拦截       └─ iOS: VPN描述文件失效
   ├─ 开启TUN模式全局断网
   └─ ChatGPT/Claude报403
```

### 维度一：按报错现象分类（Symptom-based Diagnosis）

#### 现象 1：订阅链接更新失败 / 导入格式不识别（Invalid YAML / Network Error）
- **现象描述**：将服务商下发的订阅 URL 粘贴进客户端时，弹出 `Invalid Config`、`yaml: unmarshal errors` 或请求超时。
- **排查路径**：
  1. **排查订阅地址连通性**：将订阅链接直接粘贴进浏览器地址栏，看能否正常下载并弹出一段 Base64 编码的乱文字符串。若浏览器直接提示无法连接，说明服务商下发订阅的前置域名已被运营商 DNS 污染拦截。此时可先开启其他可用代理，或查阅 [订阅链接无法连接与更新报错](/buying/subscription-issues/) 获取重命名免跨境网络加速订阅技巧；
  2. **排查格式解析兼容性**：若下载出的内容为纯单节点链接（如 `vmess://...`、`vless://...`），而你的客户端是仅接受 YAML 配置的 Clash，则无法直接识别。请前往 [实用在线工具箱](/tools) 转换为对应的 Clash 或 Sing-Box 专用格式；
  3. **排查配置缩进与非法字符**：若提示 YAML 语法错误，通常是节点命名中包含了未转义的特殊字符（如引号、冒号、Emoji 标旗字符）。检查配置文件中冒号后是否均有标准英文空格。

#### 现象 2：节点测速全部 Timeout / 显示 0ms
- **现象描述**：订阅成功导入，但在节点列表中点击“测速（Ping）”时，所有节点全部变红提示 `Timeout`，或者显示异常的 `0ms`。
- **排查路径**：
  1. **检查本地时钟与标准时间偏移**：这是引起“节点瞬间集体阵亡”的最常见原因。若电脑系统时间快或慢了 2 分钟，握手包时间戳校验将直接熔断；
  2. **检查套餐资产与流量余量**：登录服务商后台控制台，核验订阅是否因欠费到期、或月度流量用尽被后台自动封禁；
  3. **区分 TCP Ping 与 Real Ping 机制**：TCP Ping 仅测试到中转入口的延迟，而 URL Test 才会发起真实的 HTTP 请求。详细的测速机制原理与入站排障，请查阅 [节点全红 Timeout 与 0ms 诊断](/troubleshooting/timeout/)。

#### 现象 3：节点 Ping 通但无法打开任何境外网页（假连通现象）
- **现象描述**：客户端节点列表显示绿色延迟（如 80ms），但打开 Google、YouTube 时浏览器提示 `ERR_CONNECTION_CLOSED` 或连接超时。
- **排查路径**：
  1. **检查客户端系统代理开关**：确认客户端的「System Proxy」开关已处于高亮开启状态；
  2. **检查浏览器代理插件冲突**：排查是否安装了 Chrome SwitchyOmega 插件且处于固定端口模式，覆盖了系统设置；
  3. **排查本地网络环回隔离**：详细的注册表 ProxyEnable 清理步骤请参考专属长文：[连通成功但网页打不开排障手册](/troubleshooting/connected-no-internet/)。

#### 现象 4：开启 TUN 模式或系统代理后本地国内网络瘫痪
- **现象描述**：开启客户端代理后，海外网站能正常访问，但百度、微信、淘宝等国内服务加载极慢或完全断开。
- **排查路径**：
  1. **排查分流模式设置**：检查客户端是否被误操作切换成了「Global（全局模式）」。全局模式会强制让国内流量全部绕道海外机房，不仅浪费套餐高速流量，更会触发国内网银风控与异地登录验证。必须切换为 **Rule（规则分流）模式**；
  2. **更新本地 GeoIP 与 GeoSite 数据库**：若分流规则数据库版本过旧，未收录新增的国内 CDN 域名，会导致其被误判走代理；
  3. **排查 DNS 泄露与递归解析**：确保国内域名交由本地运营商 DNS（如 `223.5.5.5`）直连解析，具体配置详见 [DNS 污染劫持与真实 IP 泄漏排查](/troubleshooting/dns-leak/)。

#### 现象 5：常规网页秒开，但访问 ChatGPT/Claude 报 403 或 1020
- **现象描述**：能流畅观看 YouTube 4K 视频，但访问 OpenAI 或 Anthropic 官网时遭遇 Cloudflare 阻断或提示 `Access Denied 403`。
- **排查路径**：
  1. **定位机房 ASN 与欺诈分**：目标大模型平台对数据中心机房（Data Center）IP 实施了高强度风控；
  2. **策略组精准指定分流**：在客户端配置规则中，单独将 `DOMAIN-KEYWORD,openai` 路由至纯净的原生住宅节点，详见 [AI 生产力节点推荐榜单](/rankings/ai-services/)。

### 维度二：按客户端内核分类（Core-based Diagnosis）

不同的代理客户端底层采用不同的开发内核。理解内核的专有特性有助于直击故障根源：

#### 1. Mihomo / Clash 内核（Mihomo / Clash Verge Rev / Clash Nyanpasu）
- **Fake-IP 模式地址池冲突**：Mihomo 默认采用 `fake-ip` 机制将域名映射为 `198.18.0.0/16` 保留网段。如果本地路由器 DHCP 分配的网段恰好也是此段，或者浏览器开启了 DoH（安全 DNS），会导致解析彻底死锁。排障时可临时将配置中的 `enhanced-mode` 改为 `redir-host`；
- **TUN 虚拟网卡驱动依赖**：Windows 端依赖 `wintun.dll`。若安全软件拦截了驱动加载，会引发核心崩溃断网。

#### 2. Xray / V2Ray 内核（v2rayN / v2rayNG）
- **TLS 证书与时间戳强校验**：Xray 核心对 VMess / VLESS Reality 的时间戳同步要求极其严苛，误差必须控制在 90 秒内；
- **核心日志输出路径**：在客户端主界面按 `F12` 或查看底部「Log」窗口。若出现 `x509: certificate signed by unknown authority`，通常为杀毒软件对 HTTPS 实施了中间人解密扫描，关闭杀毒软件的 Web 监控防护即可。

#### 3. Sing-Box 内核（Sing-Box 原生客户端）
- **Inbound 监听权限不足**：Sing-Box 在 macOS 与 Linux 上使用非 Root 权限运行时，若尝试绑定 80/443 或创建 TUN 设备，会报错 `operation not permitted`；
- **JSON 路由逻辑严苛**：Sing-Box 的 Route 模块遵循严格的从上到下匹配原则，如果自定义规则中存在空字段或未闭合数组，内核会直接静默退出。

### 维度三：按操作系统平台分类（OS-based Diagnosis）

#### 1. Windows 操作系统（Win 10 / Win 11）
- **注册表死锁高发区**：当客户端被任务管理器强制终止或电脑意外蓝屏时，注册表中的代理开关未被还原。
  * **一键排查命令（PowerShell 管理员模式）**：
    ```powershell
    Get-ItemProperty -Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select-Object ProxyEnable, ProxyServer
    ```
- **UWP 应用网络隔离**：Windows 应用商店中的应用默认受沙盒限制，无法访问 `127.0.0.1` 本机代理端口。需要使用客户端自带的「UWP 工具」或运行系统自带的 `CheckNetIsolation.exe` 批量放行。

#### 2. macOS 操作系统（Sequoia / Sonoma）
- **网络扩展（Network Extension）系统授权**：首次启动开启系统代理或 TUN 时，macOS 会在「系统设置」->「隐私与安全性」中拦截网络扩展，必须手动点击「允许」；
- **Wi-Fi 与以太网接口独立代理**：macOS 的代理设置是绑定在具体网卡上的。若从 Wi-Fi 切换为网线连接，需在客户端中重新开关一次「System Proxy」。

#### 3. iOS 操作系统（Shadowrocket 小火箭 / Loon）
- **VPN 描述文件失效**：iOS 经常在系统大版本更新后导致本地安装的 VPN 虚拟网卡描述文件损坏，表现为点击小火箭开关瞬间弹回。解决办法是：进入 iOS「设置」->「通用」->「VPN 与设备管理」，删除原有 VPN 配置后重新打开小火箭授权安装；
- **首次安装蜂窝网络权限被禁**：国行 iPhone 首次安装小火箭时，若未弹出“允许使用无线局域网与蜂窝网络”弹窗，App 将无法获取任何数据。需在系统设置中找到 Shadowrocket 并放行联网权限。

## 04 常见故障深度 FAQ 矩阵（高搜索意图问答）

### Q1：为什么节点全部显示绿色（延迟几十毫秒），打开网页却一直提示网络连接超时？
> **Direct Answer**：客户端测速面板中的“绿色数字”（如 45ms）通常仅仅是 **TCP Ping 测试**，它只代表你的电脑到服务商国内前置入口服务器发起的单次握手耗时，**完全不能证明从国内入口到海外落地节点、再到目标网站的整条链路是通畅的**。
> 最典型的三大原因包括：
> 1. 本地系统代理端口未被浏览器接管，或注册表死锁；
> 2. 服务商的国内入口与海外出口之间的内网链路断流，出口流量无法转发；
> 3. 本地操作系统时间偏差导致 TLS 握手在海外节点侧被静默丢弃。
> 详情请依据 [连通成功但网页打不开](/troubleshooting/connected-no-internet/) 的排查步骤依次检验。

### Q2：电脑重启或者关闭客户端后，连百度都打不开了，怎么彻底清理残留代理？
> **Direct Answer**：这是由于代理客户端在异常退出、系统断电关机或蓝屏崩溃时，**未能正常向 Windows 注册表发送清除代理指令**所致。此时操作系统仍然误认为代理程序在后台运行，将全机流量强行导向一个已经关闭的本地端口（如 `127.0.0.1:7890`），造成全面断网。
> **秒级恢复方案**：
> 1. 按快捷键 `Win + R`，在运行框中输入 `inetcpl.cpl` 回车打开「Internet 属性」；
> 2. 切换到「连接」选项卡，点击右下角的「局域网设置（LAN Settings）」；
> 3. **取消勾选**“为 LAN 使用代理服务器”以及“自动检测设置”，点击确定保存，浏览器即可瞬间恢复直连上网。

### Q3：TUN 模式和普通系统代理模式有什么区别，排障时为什么建议先关 TUN？
> **Direct Answer**：
> - **系统代理（System Proxy）**：工作在应用层（L7），仅被动向操作系统注册 HTTP/Socks5 代理端口。只有遵循系统环境变量的浏览器能自动接入，对 Git 命令行、Telegram、大型游戏和部分 UWP 应用无效；
> - **TUN 模式（虚拟网卡）**：工作在网络层（L3），在系统中创建一张真实的虚拟网卡驱动（Wintun），通过修改系统全局路由表将全量 IP 数据包强行抓取进代理内核。
> **为什么排障时建议先关 TUN？** 因为 TUN 模式接管了操作系统的三层网络路由，一旦虚拟网卡驱动出现崩溃、跃点冲突或路由循环，会造成不可逆的全局断网。排障时先关闭 TUN 并退回系统代理模式，能够快速隔离出故障究竟是出在虚拟网卡驱动层还是底层网络层。具体修复技术可查阅 [TUN 虚拟网卡模式启动断网与驱动冲突](/troubleshooting/tun-failure/)。

### Q4：客户端日志频繁提示“net/http: TLS handshake timeout”到底代表网络被封还是本地原因？
> **Direct Answer**：该报错代表**客户端与服务端在建立 TLS 安全传输层会话时，无法在规定时限（通常为 5~15 秒）内完成密码学握手交换**。
> - **若所有节点同时报此错误**：95% 为本地原因——本机时钟与互联网标准时间偏差过大，或者本地杀毒软件劫持了根证书；
> - **若仅单个节点报此错误**：代表该特定节点的海外 IP 正在遭受国际出口网关的 SNI 阻断与 TCP RST 注入阻断，或者服务端证书已到期未及时续期。

### Q5：使用第三方在线订阅转换平台会不会导致订阅链接解析异常？
> **Direct Answer**：是的，公共订阅转换平台是引发配置报错与隐私泄露的重灾区。
> 1. **格式不匹配**：公共转换后端若模板过旧，生成的 YAML 配置可能包含已被新版内核废弃的字段，引发 `yaml: unmarshal errors`；
> 2. **Token 被盗刷**：公共平台会完整记录经过的订阅 URL，极易导致私有流量凭据泄露；
> 3. **网络死锁**：若转换服务器位于境外，而你本地当前处于无网状态，客户端在尝试拉取转换链接时会因连不上境外服务器而陷入死锁。建议优先使用客户端本地原生解析，或参考 [在线工具箱](/tools) 了解纯本地脱敏转换规范。

### Q6：同一节点在手机端使用极其流畅，为什么在电脑端连上就断网？
> **Direct Answer**：既然手机端在相同 Wi-Fi 网络下能流畅使用，说明**服务商节点本身是绝对健康的，问题 100% 出在电脑本机的客户端配置或操作系统环境上**。
> 请按以下顺序在电脑端排查：
> 1. **检查电脑系统防火墙与杀毒软件**：是否误将客户端核心进程（如 `mihomo-windows-amd64.exe`）的入站/出站网络连接拦截；
> 2. **检查本地端口冲突**：电脑上是否同时运行了其他 VPN 软件、网游加速器或旧版代理工具，占用了 `7890` 端口；
> 3. **重置 Windows 网络协议栈**：管理员身份运行 CMD 输入 `netsh winsock reset` 并重启电脑，彻底清除被第三方软件破坏的套接字层。

## 05 结语：构建具备容灾能力的高可用网络体系

排障的最高境界是“无需排障”。在现代网络环境中，单点依赖是所有断网事故的根源。无论多么昂贵的服务商，都无法保证在骨干网海缆维护或跨国路由震荡期维持 100% 不断流。

建议遵循成熟的网络工程冗余原则：
1. **多协议与双服务商容灾**：设备中同时保持主力专线与轻量备份两家独立订阅，当一家入口发生阻断时可秒级切换；
2. **掌握三层排错直觉**：熟练运用本指南推荐的三层金字塔模型，遇故障先看日志、后查时钟与代理，告别盲目焦虑；
3. **深入各专项排查分支**：收藏本站 [排障总览与故障诊断树](/troubleshooting/)，在遇到具体报错时直接跳转至对应的专项手册获取秒级解决方案。
